Prompts del Sistema Chat Academias

1. Contexto

El sistema utiliza GPT-4o mediante la API de OpenAI para generar consultas SQL a partir de lenguaje natural. Los prompts están implementados en PromptOpenAi.java (671 líneas) y controlan:

  • Definición del rol del modelo (agente SQL especializado)
  • Contexto del esquema de base de datos
  • Resolución de claves foráneas implícitas
  • Validaciones y restricciones
  • Formato de respuesta JSON

2. Estructura del Prompt Principal

El prompt se compone de varias secciones concatenadas:

// 1. DEFINICIÓN DE ROL
Eres un agente especializado en generar consultas SQL seguras y eficientes
para una base de datos académica...

// 2. ESQUEMA DE DATOS
Base de datos: ${nombreBaseDatos}
Tablas disponibles: ${listaTablas}
Restricciones de privacidad: Solo datos de academiaId=${academiaId}

// 3. RESOLUCIÓN FK
Cuando el usuario mencione "mis alumnos", generar JOIN con tabla alumnos
filtrando por profesorId=${usuarioId}...

// 4. FORMATO RESPUESTA
{
  "consulta": "SELECT ...",
  "explicacion": "Esta consulta obtiene...",
  "necesitaAprobacion": false
}

3. Ejemplo Real de Prompt FK

Fragmento simplificado de resolución de claves foráneas implícitas:

IMPORTANTE: Resolución automática de FK implícitas

Si el usuario pregunta por "mis alumnos" o "alumnos que tengo":
- Tabla: alumnos
- JOIN con asignaciones: alumnos.alumnoId = asignaciones.alumnoId
- Filtro: asignaciones.profesorId = ${usuarioId}
- Añadir: AND alumnos.academiaId = ${academiaId}

Si pregunta por "mis grupos" o "grupos que imparto":
- Tabla: grupos
- JOIN con asignaciones_grupos: grupos.grupoId = asignaciones_grupos.grupoId
- Filtro: asignaciones_grupos.profesorId = ${usuarioId}
- Añadir: AND grupos.academiaId = ${academiaId}

4. Limitaciones Conocidas

  • Ambigüedad semántica: Preguntas como "¿cuántos tengo?" requieren contexto adicional que no siempre se infiere correctamente
  • FK complejas: Relaciones multi-tabla pueden generar JOINs incorrectos o incompletos
  • Validaciones: El modelo a veces omite filtros de academiaId en subconsultas
  • Iteraciones: Se permiten hasta 10 llamadas GPT-4o (2 iniciales + 8 correcciones) para converger a SQL válido

5. Configuración Actual

Parámetros relevantes en application.properties:

# Límite de iteraciones para correcciones GPT-4o
secondTurnMaxExtraIterations=8

# Timeout para llamadas OpenAI (20 segundos)
openai.timeout.connect=20000
openai.timeout.read=20000

6. Mejoras Identificadas

Áreas identificadas para optimización:

  • Reducir ambigüedad mediante historial conversacional (ya implementado parcialmente)
  • Prompt dinámico basado en tablas detectadas en la pregunta (evitar enviar esquema completo)
  • Validación estructural del JSON antes de ejecutar SQL
  • Caché de patrones pregunta-SQL para consultas frecuentes
